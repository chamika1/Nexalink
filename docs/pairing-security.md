# Pairing security status

This is an **early local UI and cryptographic primitive**, not production secure pairing.

Implemented:
- P-256 device identity private key generated by Android Keystore
- Public key invitation format (version 1) and QR display
- Manual invitation import with fingerprint display
- Challenge signing and signature verification primitive
- Pairing state model and unit tests

Not implemented:
- QR camera scanning
- A transport or rendezvous/signaling mechanism
- Mutual authenticated challenge-response exchange
- Expiry and replay protection for live pairing sessions
- Proof of possession integrated into the pairing state machine
- Encrypted message/session keys and persistent trusted peer store
- Revocation, recovery and secure device deletion

**Security boundary:** Importing a QR invitation never authorizes remote control, screen viewing, location sharing, or messaging. A displayed fingerprint is not proof of identity unless independently compared through a trusted channel. Never treat UI state alone as authenticated trust.

No background access or location permissions are requested.
